# Практическое задание: LINQ-запросы в Windows Forms (Task1)

## Описание проекта
Приложение Windows Forms для анализа заказов интернет-магазина с применением сложных операторов LINQ (`GroupBy`, `Join`, `GroupJoin`, `Take`, `Skip`), агрегации данных и визуализации результатов в табличном виде (`DataGridView`).

### Вариант 1. Через командную строку (Терминал / PowerShell)
1. Откройте терминал в папке проекта.
2. Выполните команду:

## Реализованные задания

### 1. Соединение коллекций (Join и GroupJoin)
- **Внутреннее соединение (`Join`)**: Связывает заказы с категориями товаров по ключу `CategoryId == Category.Id`. Формирует проекцию: *ID заказа, Имя клиента, Название категории, Сумма заказа, Размер скидки (в %), Сумма со скидкой, Дата заказа*.
- **Групповое соединение (`GroupJoin`)**: Для каждой категории получает иерархический список заказов. Выводит: *Название категории, Базовую скидку, Общее количество заказов, Общую выручку*.
  > **Обработка пустых групп:** Категории без заказов (например, «Антиквариат») выводятся с количеством заказов `0` и суммой `0.00 ₽` без ошибок.

### 2. Группировка данных (`GroupBy`)
- Группировка заказов по идентификатору категории (`GroupBy(o => o.CategoryId)`).
- Вычисление агрегатов:
  - Идентификатор и название категории
  - Количество заказов в группе (`Count()`)
  - Общая сумма выручки (`Sum(o => o.Amount)`)
  - Средний чек (`Average(o => o.Amount)`) с защитой от деления на ноль для пустых групп.
- Интерактивная фильтрация: поле ввода «Порог выручки (₽)» отсекает группы с выручкой ниже заданного значения (`Where(g => g.TotalRevenue >= minThreshold)`).

### 3. Постраничный вывод и выборка частей (`Take` и `Skip`)
- **Пейджинг (`Paging`)**: Метод `orders.Skip((pageNumber - 1) * pageSize).Take(pageSize)`.
  - Динамический расчет числа страниц: `Math.Ceiling(TotalCount / PageSize)`.
  - Кнопки **«< Назад»** и **«Вперед >»** автоматически блокируются на граничных страницах.
  - Настройка размера страницы (NumericUpDown `numPageSize`).
  - Метка `lblPageInfo` показывает текущую страницу и общее количество записей.
- **ТОП-заказы**: Отбор 3 самых дорогих заказов через `OrderByDescending(o => o.Amount).Take(3)`.
- **Срез списка**: Пропуск первых N устаревших заказов (`OrderBy(o => o.OrderDate).Skip(N)`).

## Вопросы и ответы для устной защиты работы

### 1. В чем разница между операторами LINQ Join и GroupJoin?
- **Join (Inner Join):** сопоставляет каждый элемент левой коллекции с соответствующим элементом правой по ключу. Если для элемента нет пары, он **исключается** из результата (плоский список 1-к-1 или 1-к-Многим).
- **GroupJoin (Left Outer / Hierarchical Join):** для каждого элемента левой коллекции возвращает коллекцию всех совпадающих элементов правой (`IEnumerable<TInner>`). Если совпадений нет, элемент не теряется, а получает пустую коллекцию (`Count == 0`).

### 2. Какую структуру имеет результат выполнения метода GroupBy (что представляет собой `IGrouping<TKey, TElement>`)?
Метод `GroupBy` возвращает `IEnumerable<IGrouping<TKey, TElement>>`. Интерфейс `IGrouping<TKey, TElement>` наследует `IEnumerable<TElement>` и дополняет его свойством `Key` типа `TKey`. Таким образом, каждый объект группы — это перечисление элементов, объединенных общим ключом.

### 3. Как работает комбинация методов Skip(N) и Take(M) при реализации постраничного вывода?
- `Skip(N)` пропускает первые $N$ элементов (для страницы: `(pageNumber - 1) * pageSize`).
- `Take(M)` выбирает следующие $M$ элементов (`pageSize`).
Вместе они создают «скользящее окно» выборки нужного диапазона без избыточной загрузки всего набора данных.

### 4. В каком порядке необходимо вызывать OrderBy, Skip и Take для корректной сортировки пагинированных данных?
Строго в порядке: **`OrderBy` $\rightarrow$ `Skip` $\rightarrow$ `Take`**.
Сначала весь набор упорядочивается, и только затем отбирается нужный сегмент. Если вызвать `OrderBy` после `Skip`/`Take`, упорядочена будет лишь текущая страница, что нарушит целостность постраничного вывода.
